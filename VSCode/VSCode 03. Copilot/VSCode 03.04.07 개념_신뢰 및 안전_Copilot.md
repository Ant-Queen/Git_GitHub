# VS Code Copilot 신뢰 및 안전 개요

## 개요

Copilot 에이전트는 파일 읽기, 코드 편집, 터미널 명령 실행, 외부 서비스 호출 등을 수행할 수 있습니다. VS Code는 이러한 동작을 안전하게 제어하기 위해 여러 신뢰 및 안전 메커니즘을 제공합니다.

## 1. 제어 유지하기

### 변경 사항 검토
- 에이전트가 생성한 코드 변경 사항은 diff 뷰로 표시됩니다.
- 각 변경을 검토하고 개별 편집을 수락 또는 거부할 수 있습니다.
- 저장 전에 코드를 직접 수정할 수도 있습니다.

### 체크포인트 사용
- 에이전트 세션은 작업 진행 중 체크포인트를 만듭니다.
- 잘못된 방향으로 진행될 경우 이전 체크포인트로 돌아갈 수 있습니다.

### 도구 호출 승인
- 터미널 명령이나 사이드 이펙트가 있는 도구 사용 전에 사용자 승인 요청이 표시됩니다.
- `Chat: Manage Tool Approval` 명령으로 모든 도구 승인 상태를 중앙에서 관리할 수 있습니다.

### 권한 수준 선택
- Default Approvals: 민감한 도구에 대해 확인을 요구합니다.
- Bypass Approvals: 모든 도구 호출을 자동 승인합니다.
- Autopilot (Preview): 질문에 자동으로 응답하고 자율적으로 작업을 계속합니다.
- 높은 자율성을 사용할 때에는 에이전트 샌드박싱 또는 컨테이너와 함께 사용하는 것이 안전합니다.

### 신뢰 경계
- VS Code는 파일 액세스, URL 액세스, 에이전트 샌드박싱, MCP 서버 상호작용에 대한 보안 경계를 적용합니다.

### 최종 권장
- AI가 생성한 코드는 항상 최종 검토가 필요합니다.\n- 엣지 케이스, 프로젝트 컨벤션, 보안 이슈를 확인해야 합니다.

## 2. 에이전트 샌드박싱

### 샌드박싱의 필요성
- 승인 기반 보안은 사용자가 모든 명령을 주의 깊게 검토해야 합니다.
- 반복 승인으로 인한 피로는 부주의를 유발할 수 있습니다.
- 복잡한 쉘 구문이나 별칭은 자동 승인 규칙을 우회할 수 있습니다.
- 프롬프트 인젝션 또는 악성 입력이 에이전트를 조작할 수 있습니다.
- 외부 서비스에 대한 액세스는 취소하기 어려운 작업을 수행할 수 있습니다.

### 샌드박싱 작동 원리
- 파일 시스템 격리와 네트워크 격리를 OS 수준에서 적용합니다.
- 샌드박싱된 명령은 명시적으로 허용된 범위 내에서만 실행됩니다.
- 추가 권한이 필요한 경우 VS Code는 명령을 샌드박스 외부에서 실행하도록 요청합니다.

### 파일 시스템 격리
- 기본 동작: 작업 폴더와 샌드박스 런타임 임시 폴더에 대한 읽기 액세스 허용.
- 홈 디렉터리(`$HOME`)로부터의 읽기는 기본적으로 차단됩니다.
- SSH 키, 셸 구성 파일 등 민감한 파일 보호.
- 쓰기 액세스는 현재 작업 디렉터리 및 하위 디렉터리로 제한됩니다.
- 명령 실행 전에 필요한 경로를 파싱하여 해당 경로에 대한 읽기 권한을 부여합니다.
- 추가 경로 허용 또는 차단 규칙을 구성할 수 있습니다.
- 차단 규칙이 허용 규칙보다 우선합니다.
- 자식 프로세스는 동일한 파일 시스템 제한을 상속받습니다.

### 네트워크 격리
- 기본적으로 모든 아웃바운드 연결을 차단합니다.
- `chat.agent.sandbox.enabled` 설정이 `on`이면 네트워크 액세스가 차단됩니다.
- `allowNetwork` 모드에서는 네트워크 액세스를 허용하되 파일 시스템 제한은 유지됩니다.
- 도메인 필터링을 사용해 허용 도메인을 지정할 수 있습니다.
- `chat.agent.allowedNetworkDomains` 및 `chat.agent.deniedNetworkDomains` 설정으로 도메인을 제어합니다.
- 허용된 도메인으로는 요청된 작업을 수행할 수 있으므로 신중하게 구성해야 합니다.
- 자식 프로세스도 동일한 네트워크 제한을 상속합니다.

### OS 수준 강제 적용
- 샌드박싱은 커널 수준 보안 프리미티브를 사용합니다.
- 샌드박스된 프로세스와 모든 자식 프로세스는 경계를 우회할 수 없습니다.
- macOS: Apple's sandboxing framework(`Seatbelt`) 사용.
- Linux 및 WSL2: `bubblewrap`과 `socat`을 사용.
- Windows: WSL2를 기반으로 샌드박싱을 지원합니다.
- WSL1은 지원되지 않습니다.

### 샌드박싱의 제한 사항
- 샌드박싱은 터미널 명령(`runInTerminal`)에만 적용됩니다.
- 내장 파일 도구는 VS Code의 자체 권한 시스템을 통해 제어됩니다.
- 네트워크 필터링은 샌드박싱 외에도 에이전트 도구에 적용됩니다.
- 샌드박싱과 네트워크 필터링이 모두 활성화된 경우, 모든 도구와 터미널 명령에 규칙이 적용됩니다.

### 개발 환경 격리 권장
- 완전한 환경 격리를 위해 Dev Container와 함께 사용합니다.
- Dev Container는 전체 개발 환경, 파일 액세스, 네트워크 액세스를 경계로 감쌉니다.
- 샌드박싱은 현재 미리 보기 기능이며 계속 진화하고 있습니다.

## 3. AI 한계에 주의하기

- AI 모델은 겉보기에는 올바른 코드라도 버그가 있거나 구식 API를 사용하거나 엣지 케이스를 처리하지 못할 수 있습니다.
- 프롬프트 인젝션 공격은 파일, 도구 출력, 웹 페이지의 악성 콘텐츠를 통해 에이전트를 조작하려 할 수 있습니다.
- VS Code는 이러한 위험을 줄이기 위해 도구 승인 장치와 신뢰 경계를 제공합니다.
- AI 출력은 항상 초안으로 간주하고 사용자 검토가 필요합니다.
- 모델의 비결정성, 지식 경계, 컨텍스트 제한을 이해해야 합니다.
