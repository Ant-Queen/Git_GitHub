# VS Code Copilot 언어 모델 개요 정리

## 언어 모델이 작동하는 방식

- 언어 모델은 텍스트 입력(프롬프트)을 처리하고 텍스트 출력을 생성합니다.
- VS Code에서는 프롬프트가 다음을 포함하여 조합됩니다.
  - 사용자의 메시지
  - 대화 기록
  - 파일 내용
  - 도구 출력
  - 커스텀 지침
- 모델은 코드를 실행하거나 파일에 직접 접근하지 않습니다.
- 대신 에이전트 루프가 모델 출력을 행동으로 해석하고, 필요에 따라 도구 호출을 실행한 뒤 결과를 다시 모델에 제공합니다.

## 주요 특성

- 비결정적(Nondeterministic)
  - 같은 프롬프트라도 매번 다른 결과가 나올 수 있습니다.
  - 이는 모델이 확률 분포에서 샘플링하기 때문에 발생합니다.
- 컨텍스트 의존적(Context-dependent)
  - 응답 품질은 프롬프트에 제공된 컨텍스트의 품질과 관련성에 크게 좌우됩니다.
- 지식 경계(Knowledge boundaries)
  - 모델은 특정 날짜까지의 학습 데이터로 학습됩니다.
  - 최신 정보나 학습 이후 변경된 내용에 대해서는 잘못된 답을 할 수 있습니다.
  - VS Code는 도구와 워크스페이스 인덱싱으로 이러한 문제를 완화합니다.

## 컨텍스트 윈도우

- 컨텍스트 윈도우는 모델이 한 번에 처리할 수 있는 정보의 총량입니다.
- 여기에 포함되는 항목:
  - 시스템 프롬프트
  - 커스텀 지침
  - 대화 기록
  - 파일 내용
  - 도구 출력
  - 현재 메시지
- 모델마다 컨텍스트 윈도우 크기가 다릅니다.
- 윈도우가 가득 차면 VS Code는 자동으로 이전 대화 내용을 요약하여 공간을 확보합니다.
- `/compact` 명령을 사용하면 수동으로 컨텍스트 압축을 실행할 수 있습니다.
  - 예: `/compact focus on the API design decisions`

## 사고와 추론(Thinking and reasoning)

- 일부 모델은 응답을 생성하기 전에 내부적으로 더 많은 추론을 수행할 수 있습니다.
- 사고 모델(reasoning models)은 문제를 여러 관점으로 검토하고 단계별 사고 과정을 구성합니다.
- 복잡한 문제에는 더 적합하지만, 단순 작업에서는 지연이 증가할 수 있습니다.

### 사고 노력(Thinking effort)

- 사고 노력은 모델이 각 요청에 대해 얼마나 많은 추론을 적용할지 제어합니다.
- 높은 노력 수준은 복잡한 문제에 대해 더 철저한 내부 추론을 제공하지만, 지연과 토큰 사용량이 증가합니다.
- 낮은 노력 수준은 지연을 줄이고 토큰 비용을 절감합니다.
- 일부 모델은 작업 복잡도에 따라 스스로 사고 수준을 조정하는 적응형 사고(adaptive thinking)를 지원합니다.
- 대부분의 경우 VS Code 기본값이 잘 작동합니다.

### 사고 토큰(Thinking tokens)

- 사고 토큰은 모델의 컨텍스트 윈도우에 포함됩니다.
- 하지만 최종 응답에는 보이지 않습니다.
- 높은 사고 노력 수준은 더 많은 사고 토큰을 생성할 수 있습니다.
- 결과적으로 지연이 늘어날 수 있습니다.

## 적절한 모델 선택하기

### 모델 종류별 용도

- 빠른 모델
  - 빠른 코드 편집, 보일러플레이트 생성, 간단한 질문에 적합합니다.
- 사고 모델
  - 복잡한 리팩터링, 아키텍처 결정, 다단계 디버깅 등에 적합합니다.
- 대용량 컨텍스트 모델
  - 큰 코드베이스나 긴 대화를 다룰 때 유리합니다.

- 언제든 필요에 따라 모델을 전환할 수 있습니다.
- 자세한 비교는 GitHub Copilot 문서의 모델 선택 가이드를 참고합니다.

### 자동 모델 선택(Auto model selection)

- 자동 모델 선택은 두 가지 시스템을 결합해 요청을 최적 모델로 라우팅합니다.
  - 실시간 모델 상태 및 가용성 추적
  - 작업 복잡도 평가
- 높은 비용의 추론 모델은 복잡한 문제에, 빠른 모델은 단순한 작업에 할당됩니다.
- 조직의 모델 액세스 정책이나 데이터 거주 정책에 따라 사용 가능한 모델이 제한될 수 있습니다.

### AI 크레딧과 모델 비용

- Copilot 플랜에는 월별 AI 크레딧 할당이 포함됩니다.
- 모델 및 처리 토큰 수에 따라 AI 크레딧이 소비됩니다.
- 더 강력한 모델은 토큰당 더 많은 비용을 사용하고, 가벼운 모델은 더 오랜 사용 시간을 제공합니다.
- 사고 노력, 컨텍스트 윈도우 크기, 도구 사용도 비용에 영향을 줍니다.
- AI 크레딧 사용량 최적화 문서를 참고해 비용을 줄일 수 있습니다.

## 사용자 언어 모델 키(BYOK)

### BYOK를 사용하는 이유

- 모델 선택의 폭이 넓어집니다.
- 새로운 모델이나 아직 기본 모델에 없는 기능을 실험할 수 있습니다.
- 로컬 컴퓨팅을 활용하거나 자체 모델을 사용할 수 있습니다.
- GitHub 계정, Copilot 플랜, 인터넷 연결 없이도 사용할 수 있는 로컬 모델에 적합합니다.
- 자체 모델로 표준 요금제 제한을 우회할 수 있습니다.

### 고려 사항

- BYOK는 채팅 경험과 유틸리티 작업에만 적용됩니다.
- 인라인 제안과 임베딩 기반 기능(예: 시맨틱 검색)은 여전히 GitHub 계정이 필요합니다.
- 공급 모델에 따라 도구 호출, 비전, 사고 지원 여부가 달라질 수 있습니다.
- BYOK 사용 시 출력에 대한 책임 있는 AI 필터링이 보장되지 않을 수 있습니다.
