# VS Code Copilot 에이전트 개요 정리

## 개요

에이전트는 VS Code에서 자율적으로 코딩 작업을 실행하는 AI 시스템입니다. 사용자는 높은 수준의 목표를 제시하고, 에이전트는 이를 단계로 분해해 파일 편집, 명령 실행, 코드 검증 등을 반복하면서 작업을 완성합니다.

## 에이전트 루프

에이전트는 일반적으로 다음 3단계로 작동합니다.

1. 이해(Understand)
   - 파일을 읽고 코드베이스를 검색하며 문서를 확인해 무엇을 변경해야 하는지 파악합니다.
2. 실행(Act)
   - 코드 수정, 터미널 명령 실행, 종속성 설치, 외부 서비스 호출 등 도구를 사용해 작업을 수행합니다.
3. 검증(Validate)
   - 테스트 실행, 컴파일 오류 확인, 자신의 변경 사항 검토를 통해 결과를 검증합니다.

- 각 단계의 출력은 다음 결정에 대한 입력으로 사용됩니다.
- 모델은 스스로 행동을 계획하고 도구 호출을 선택합니다.
- 툴 호출 결과는 컨텍스트에 추가되어 다음 반복에 반영됩니다.
- 기능 구현은 편집, 테스트, 진단, 재수정 과정을 반복하는 루프로 진행될 수 있습니다.

### 에이전트 루프 커스터마이즈

- 커스텀 에이전트: 각기 다른 페르소나, 지침, 사용 가능한 도구, 언어 모델을 정의할 수 있습니다.
- 에이전트 스킬: 특정 도메인이나 작업에 대한 새로운 역량을 가르칩니다.
- 후크(Hooks): 에이전트 루프의 특정 라이프사이클 지점에서 커스텀 명령을 실행합니다.

## 에이전트 유형

에이전트는 어디에서 실행되는지와 어떻게 상호작용하는지에 따라 구분됩니다.

- 로컬 에이전트(Local agents)
  - VS Code 내에서 인터랙티브하게 실행됩니다.
- 백그라운드 에이전트(Background agents)
  - 로컬 머신에서 자율적으로 실행됩니다.
- 클라우드 에이전트(Cloud agents)
  - GitHub 인프라에서 실행되어 원격 협업 워크플로를 지원합니다.
- 타사 에이전트(Third-party agents)
  - Anthropic, OpenAI 등 외부 AI 공급자가 제공하는 에이전트를 연결할 수 있습니다.

- 적합한 에이전트 유형 선택을 위해 작업 종류와 감독 수준을 고려합니다.

## 서브에이전트(Subagents)

복잡한 작업에서는 메인 에이전트가 서브에이전트에게 하위 작업을 위임할 수 있습니다.

- 컨텍스트 최적화: 서브에이전트는 자체 컨텍스트 창을 사용하므로 메인 에이전트의 컨텍스트가 과도하게 차지되지 않습니다.
- 동기 실행: 메인 에이전트는 서브에이전트 결과를 기다린 후 다음 작업을 결정합니다.
- 병렬 실행: 보안, 성능, 접근성 분석 등 여러 서브에이전트가 동시에 실행될 수 있습니다.
- 집중된 결과: 서브에이전트는 최종 결과만 메인 에이전트에 반환합니다.

- 예: Plan 에이전트는 연구와 분석을 위해 서브에이전트를 사용한 뒤 계획을 작성합니다.

## 코드 중심 vs 에이전트 중심

- 코드 중심(Code-first)
  - 개발자가 에디터에서 직접 코드를 작성하며 AI는 보조 역할을 합니다.
  - 주요 인터페이스는 편집기이며, AI는 코드 구현, 수정, 디버깅을 돕습니다.
- 에이전트 중심(Agent-first)
  - 대화형 채팅에서 작업을 정의하고 에이전트가 계획 및 실행을 담당합니다.
  - 주요 인터페이스는 채팅과 세션 목록이며, 에디터는 결과 검토 및 수정 용도로 사용됩니다.

- 두 방식은 동시에 사용할 수 있으며, 에이전트 창과 VS Code 편집기 창이 세션과 설정을 공유합니다.

## 원격 에이전트 세션

에이전트 세션을 로컬이 아닌 원격 호스트에서 실행할 수 있습니다.

- 멀리 떨어진 장치의 리소스를 활용하거나, 세션을 계속 실행하면서 다른 기기에서 모니터링할 수 있습니다.
- 원격 머신은 네트워크로 접근 가능해야 합니다.

지원 방식:
- 원격 연결된 에이전트 창: SSH 또는 dev tunnel을 통해 에이전트 호스트 프로세스를 실행하고 여러 클라이언트가 동기화된 방식으로 연결합니다.
- Copilot CLI 원격 제어: `/remote on` 명령으로 세션을 GitHub에 미러링하여 웹 또는 모바일 앱에서 모니터링 및 제어합니다.

## 메모리(Memory)

에이전트는 대화 간 맥락을 유지하기 위해 메모리를 사용합니다.

### VS Code 메모리 시스템

- 메모리 도구(Memory tool): 로컬에 메모리를 저장합니다.
  - 사용자 메모리(`/memories/`): 모든 워크스페이스와 대화에서 사용할 수 있는 영구 메모리
  - 저장소 메모리(`/memories/repo/`): 현재 작업 공간에 국한된 영구 메모리
  - 세션 메모리(`/memories/session/`): 현재 대화에 국한되며 대화가 끝나면 삭제됨

### Copilot Memory

- GitHub 호스팅 메모리 시스템으로, Copilot의 여러 표면(코딩 에이전트, 코드 리뷰, CLI)에서 저장소별 인사이트를 공유합니다.

## 계획(Planning)

복잡한 작업의 경우 바로 코드 생성으로 들어가면 설계가 부정확할 수 있습니다. Plan 에이전트는 실제 코드를 변경하기 전에 먼저 작업을 연구하고 계획을 세웁니다.

Plan 에이전트의 4단계 워크플로:
1. 탐색(Discovery): 읽기 전용 도구와 코드베이스 분석으로 작업 조사
2. 정렬(Alignment): 모호한 부분을 해결하기 위한 명확화 질문
3. 설계(Design): 구조화된 구현 계획 초안 작성
4. 개선(Refinement): 피드백을 반영해 계획을 다듬음

- Plan 에이전트는 계획이 검토되고 승인될 때까지 코드 변경을 수행하지 않습니다.
- 승인 후 기본 에이전트에 계획을 전달하거나 추가 개선을 계속할 수 있습니다.
