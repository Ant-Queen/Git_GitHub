# VS Code Copilot 컨텍스트 개요 정리

## 개요

컨텍스트는 모델이 응답을 생성할 때 볼 수 있는 모든 정보입니다. 대화 기록, 파일 내용, 도구 출력, 커스텀 지침 등 현재 요청에 포함된 정보만 모델이 인식할 수 있습니다.

## 컨텍스트가 중요한 이유

- 관련 파일과 명확한 지침이 포함된 프롬프트가 더 좋은 결과를 만듭니다.
- 모델은 이전 세션을 기억하지 않으며, 주어지지 않은 파일에 접근할 수 없습니다.
- 현재 작업에 대한 모든 정보는 해당 요청에 조합된 컨텍스트에서 제공됩니다.

## VS Code가 컨텍스트를 구성하는 방식

VS Code는 메시지를 보낼 때 다음 항목을 결합하여 언어 모델 프롬프트를 만듭니다.

- 시스템 지침: 에이전트 동작을 정의하는 내장 규칙
- 커스터마이제이션: 커스텀 에이전트, 스킬, 커스텀 인스트럭션 등
- 사용자 메시지: 현재 사용자가 입력한 내용
- 대화 기록: 현재 세션의 이전 메시지
- 암묵적 컨텍스트: 편집 중인 파일, 현재 선택 영역, 표시된 오류, Git 상태
- 명시적 참조: `#file` 등의 방식으로 참조한 파일, 웹 콘텐츠 등
- 도구 출력: 파일 읽기, 터미널 명령, 코드베이스 검색 결과 등 도구 호출 결과

> 모델이 볼 수 있는 것은 이 조합된 프롬프트뿐이며, 그 밖의 정보는 보이지 않습니다.

## 워크스페이스 인덱싱

VS Code는 코드베이스를 빠르고 정확하게 검색하기 위해 인덱스를 사용합니다.

- 원격 인덱스(Remote index): GitHub 저장소에 호스팅된 경우 빠른 검색을 위해 사용
- 로컬 인덱스(Local index): 로컬 머신에 저장된 고급 의미 기반 인덱스
- 기본 인덱스(Basic index): 로컬 인덱스를 사용할 수 없는 경우 간단한 알고리즘으로 동작

## 암묵적 컨텍스트

VS Code는 사용자의 현재 활동에 따라 자동으로 다음과 같은 컨텍스트를 제공합니다.

- 활성 편집기에서 선택된 텍스트
- 활성 편집기의 파일 이름 또는 노트북 이름
- Ask 에이전트를 사용하는 경우 활성 파일이 자동으로 컨텍스트에 포함
- Agent 사용 시 현재 파일이 필요한지 에이전트가 자율적으로 판단하여 추가

## 컨텍스트를 효과적으로 사용하는 방법

- 새 작업마다 새로운 세션을 시작합니다.
  - 세션은 독립적인 대화로 각자의 컨텍스트 창과 기록을 가집니다.
  - 관련 없는 작업을 하나의 대화에 계속 사용하지 마세요.
- 필요한 컨텍스트를 선택적으로 제공합니다.
  - 전체 코드베이스를 추가하는 것이 항상 도움이 되지는 않습니다.
  - 작업과 관련된 특정 파일을 참조하는 것이 더 효과적입니다.
- 커스텀 인스트럭션을 사용하여 지속적인 규칙을 설정합니다.
  - 커스텀 인스트럭션은 요약이 발생해도 각 요청에 포함됩니다.

## 예시

- 모호한 프롬프트:
  ```text
  How does authentication work?
  ```
  - 모델은 어떤 프로젝트를 의미하는지 알 수 없어 일반적인 인증 패턴을 답할 수 있습니다.

- 명시적 컨텍스트가 포함된 프롬프트:
  ```text
  How does authentication work for this project?
  ```
  - 모델은 실제 인증 파일을 읽고 구현 방식을 설명하며 특정 함수와 설정 값을 참조할 수 있습니다.

- 웹 컨텍스트를 포함한 프롬프트:
  ```text
  Migrate the auth module to the latest passport.js API #fetch https://www.passportjs.org/concepts/authentication/
  ```
  - 모델은 최신 문서를 참고하여 오래된 API 패턴을 피하면서 마이그레이션을 안내할 수 있습니다.
