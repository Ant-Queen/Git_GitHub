# VS Code 에이전트 보안 정리

원문: https://code.visualstudio.com/docs/agents/security

---

## 1. 한 줄 요약

VS Code 에이전트는 승인, 격리, 샌드박싱, 신뢰 경계 같은 보안 메커니즘을 통해 위험한 작업을 제한하고, 사용자가 안전하게 제어할 수 있도록 설계되어 있습니다.

---

## 2. 기본 보안 원칙

AI 기반 개발은 자동으로 파일 수정, 명령 실행, 네트워크 접근을 시도할 수 있기 때문에 보안 설정이 중요합니다.

가장 기본적인 원칙은 다음과 같습니다.

- 신뢰하지 않는 프로젝트는 먼저 검토한 뒤 열기
- 민감한 파일은 수동 승인으로 보호하기
- 자동 승인 권한은 세션 단위로만 제한하기
- MCP 서버와 외부 도메인에 대한 신뢰 여부를 확인하기

---

## 3. 신뢰 경계(Trust boundaries)

VS Code는 여러 수준의 신뢰 경계를 사용합니다.

- 워크스페이스: 신뢰되지 않은 워크스페이스는 제한 모드로 동작합니다.
- 확장 프로그램 게시자: 신뢰하는 게시자만 실행 가능하게 할 수 있습니다.
- MCP 서버: 서버를 실행하기 전에 사용자가 신뢰 여부를 판단합니다.
- 네트워크 도메인: 외부 URL 접근 전에 승인해야 합니다.

이 구조는 에이전트가 실수로 또는 악의적으로 너무 넓은 범위에 접근하는 것을 막아 줍니다.

---

## 4. 환경 보호 방식

VS Code는 다음과 같은 방식으로 에이전트의 영향을 제한합니다.

- 워크스페이스 범위로 파일 접근 제한
- 필요한 도구만 활성화하여 권한 축소
- 세션 단위 권한 부여
- 과도한 작업을 막는 요청 제한
- 배경 에이전트와 클라우드 에이전트의 격리된 실행

즉, 에이전트가 “내 환경 전체를 마음대로 건드리지 못하게” 보호하는 구조입니다.

---

## 5. 승인과 검토 흐름

VS Code는 위험한 동작에 대해 승인 과정을 둡니다.

### 권한 수준

- 기본 승인: 필요 시 승인 요청
- Bypass Approvals: 자동 승인
- Autopilot: 더 넓은 자동 실행

### 검토 포인트

- 터미널 명령 실행 전 승인 요청
- MCP 도구 호출 시 승인 요청
- 파일 변경은 diff 편집기로 확인 후 반영
- URL 접근은 도메인 신뢰와 내용 검토를 거침

---

## 6. 샌드박싱과 격리

### 에이전트 샌드박싱

- OS 수준 격리로 터미널 실행과 네트워크 접근 범위를 제한합니다.
- 승인되어도 샌드박스 밖으로 접근하지 못하게 막는 강력한 보호 장치입니다.

### MCP 서버 샌드박싱

- 로컬 MCP 서버도 접근 가능한 경로와 도메인을 제한할 수 있습니다.
- 격리된 환경에서 실행되므로 더 안전합니다.

---

## 7. 보안 리스크

다음과 같은 위험이 있을 수 있습니다.

- 실행 및 접근 권한 남용
- 의존성 및 공급망 문제
- 과도한 자동 승인으로 인한 실수
- 민감한 정보 노출
- 프롬프트 인젝션 공격

이런 위험을 줄이려면 자동 승인 범위를 제한하고, 샌드박싱과 승인 절차를 함께 쓰는 것이 좋습니다.

---

## 8. 조직 정책

조직 차원에서는 다음과 같은 정책을 적용할 수 있습니다.

- 에이전트 사용 자체 차단
- 확장 도구 사용 제한
- MCP 서버 소스 제한
- 자동 승인 전역 비활성화
- 특정 도구에 대한 수동 승인 강제

이렇게 하면 팀 전체의 보안 기준을 일관되게 유지할 수 있습니다.

---

## 9. 핵심 정리

VS Code 에이전트 보안의 핵심은 “사용자가 위험한 동작을 직접 통제할 수 있게 하는 것”입니다. 승인, 격리, 샌드박싱, 신뢰 경계를 함께 쓰면 보다 안전하게 AI 기반 개발을 진행할 수 있습니다.
