# VS Code 에이전트 개요

Visual Studio Code의 에이전트는 AI 어시스턴트입니다. 사용자가 높은 수준의 목표를 주면 에이전트가 작업을 계획하고, 여러 파일을 수정하며, 터미널 명령을 실행하고, 필요 시 스스로 오류를 수정합니다.

에이전트를 사용하면 단순한 제안이 아니라 프로젝트 전체를 대상으로 기능 구축, 디버깅, 테스트, 리팩터링, 풀 리퀘스트 제출 같은 엔드투엔드 작업을 수행할 수 있습니다.

## 1. 에이전트와 함께 작업할 때의 주요 선택

에이전트 사용 시 다음과 같은 결정을 내릴 수 있습니다.

- 어디에서 작업할지 선택
  - 편집기 창
  - 전용 Agents 창
- 어떤 에이전트 유형을 사용할지 선택
  - 로컬
  - 백그라운드(Copilot CLI)
  - 클라우드
  - 서드파티 제공자
- 어떤 에이전트 역할을 사용할지 선택
  - 빌드, 계획, 질문 응답 등 작업에 맞는 페르소나
- 어떤 권한 수준을 부여할지 선택
  - 도구 호출과 명령 실행에 대한 에이전트 자율성 제어

필요하면 한 에이전트 세션을 다른 에이전트로 전달하여 각 유형의 장점을 활용할 수 있습니다.

## 2. 에이전트 작업 위치

VS Code는 에이전트를 사용하는 두 가지 인터페이스를 제공합니다.

- Agents 창 (에이전트 우선, Preview)
  - 단일 장소에서 여러 프로젝트를 관리하고 에이전트 세션을 조율
  - 채팅과 세션 목록이 기본 인터페이스
  - 프롬프트 중심 작업 및 프로젝트 간 오케스트레이션에 적합
- 채팅 보기 (코드 우선)
  - 편집기 탭과 함께 채팅을 표시
  - 디버거, 노트북, 확장, 원격 개발과 통합
  - 코드 작성 및 편집 중심 작업에 적합

두 인터페이스는 동일한 에이전트 세션과 VS Code 설정, 키바인딩을 공유하므로 부드럽게 전환할 수 있습니다.

## 3. 에이전트 유형

에이전트는 실행되는 환경에 따라 구분됩니다.

- 로컬 에이전트
  - VS Code 내에서 대화형으로 작동
  - 워크스페이스, 도구, 모델에 전체 접근 가능
- Copilot CLI
  - 로컬 백그라운드 실행
  - Git worktree를 사용하여 분리된 작업 가능
- 클라우드 에이전트
  - GitHub Copilot 기반 원격 실행
  - 팀 리뷰용 풀 리퀘스트와 통합
- 서드파티 에이전트
  - Anthropic, OpenAI 등의 외부 모델 제공자 사용

에이전트 유형은 작업 결과를 얻는 위치와 감독 수준을 결정합니다.

## 4. 어떤 에이전트를 선택해야 하는가

에이전트 유형은 실행 위치를, 에이전트 자체는 작업 방식과 역할을 결정합니다.

- `Agent`
  - 자율적으로 계획을 세우고 파일 변경, 명령 실행, 도구 호출 수행
- `Plan`
  - 먼저 구조화된 단계적 실행 계획을 생성
  - 계획이 충분히 만족스러우면 구현 에이전트에 전달
- `Ask`
  - 코드베이스와 VS Code 관련 질문에 답변
  - 파일 변경을 직접 수행하지 않음

더 전문화된 워크플로우가 필요하면 커스텀 에이전트를 만들어 특정 역할, 사용할 도구, 언어 모델을 정의할 수 있습니다.

또한 세션 내에서 작업에 맞춰 모델을 선택할 수 있습니다.
- 빠른 편집과 질문에는 빠른 모델
- 복잡한 다단계 작업에는 더 높은 추론 능력을 가진 모델

## 5. 권한 수준 선택

에이전트는 도구와 터미널 명령을 실행할 수 있으므로, 사용자는 자율성을 제어할 수 있습니다.

- 기본 승인(Default Approvals)
  - VS Code 설정에 지정된 승인 규칙을 따름
  - 기본적으로 읽기 전용 및 안전 도구는 별도 승인 없이 실행
- 승인 건너뛰기(Bypass Approvals)
  - 모든 도구 호출을 자동 승인
  - 에이전트가 필요 시 추가 질문을 할 수 있음
- 오토파일럿(Autopilot, Preview)
  - 모든 도구 호출 자동 승인
  - 질문에도 자동으로 응답하며 작업을 끝까지 수행

선호 권한 수준을 계속 사용하려면 `chat.permissions.default` 설정을 구성합니다.

## 6. 에이전트 세션 전달

한 에이전트에서 다른 에이전트로 작업을 넘길 수 있습니다.

예:
- 로컬 에이전트로 계획 수립
- Copilot CLI로 개념 증명 실행
- 클라우드 에이전트로 풀 리퀘스트 제출

로컬 세션 전달 방법:
- 채팅 입력 상자의 세션 유형 드롭다운에서 다른 에이전트 유형 선택
- 전체 대화 기록과 컨텍스트가 새 세션으로 전달됨
- 원래 세션은 보관됨

Copilot CLI 세션에서는 `/delegate` 명령을 입력하여 클라우드 에이전트에 위임할 수 있습니다.
