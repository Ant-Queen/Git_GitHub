# VS Code 커스텀 에이전트 (Custom Agents)

## 개요

커스텀 에이전트는 특정 역할이나 작업을 위해 **특화된 AI 페르소나**를 정의합니다. 각 에이전트는 고유한 지시사항, 도구 접근 제한, 모델 선택을 가질 수 있습니다.

### 핵심 특징
- **역할 특화**: 특정 작업에 최적화된 설정
- **도구 제한**: 보안 정책 강제 가능
- **핸드오프**: 에이전트 간 전환 지원
- **모델 선택**: 에이전트별 모델 지정 가능
- **재사용성**: VS Code, Copilot CLI, Copilot Cloud Agent에서 사용 가능

## 왜 커스텀 에이전트를 사용하는가?

다양한 작업은 다양한 기능을 요구합니다:

- **계획 에이전트**: 읽기 전용 도구로 리서치와 계획 수립
- **구현 에이전트**: 전체 편집 기능으로 코드 작성
- **코드 리뷰 에이전트**: 보안과 품질 검증

커스텀 에이전트를 사용하면:
- 작업에 맞는 도구 선택 가능
- 의도하지 않은 변경 방지
- 매번 도구 설정 불필요
- 특화된 지시사항으로 일관된 동작

## 핸드오프 (Handoffs)

**정의**: 에이전트 간의 가이드된 순차 워크플로우를 지원합니다.

### 사용 예시

1. **계획 → 구현**
   - 계획 에이전트에서 구현 계획 생성
   - "구현 시작" 버튼으로 구현 에이전트로 전환

2. **구현 → 검토**
   - 구현 완료 후 검토 에이전트로 이동
   - 품질 및 보안 확인

3. **테스트 작성 → 구현**
   - 실패 테스트 생성
   - 테스트 통과 구현 에이전트로 전환

### 핸드오프 설정

```yaml
---
name: "계획 에이전트"
description: "구현 계획 생성"
tools: ['search', 'web']
handoffs:
  - label: "구현 시작"
    agent: implementation
    prompt: "위의 계획을 바탕으로 구현을 시작하세요."
    send: false
    model: "GPT-5.2 (copilot)"
---
```

### 핸드오프 필드

| 필드 | 설명 |
|------|------|
| **label** | 버튼에 표시되는 텍스트 |
| **agent** | 대상 에이전트 이름 |
| **prompt** | 대상 에이전트에 보낼 프롬프트 |
| **send** | true면 프롬프트 자동 전송, false면 사용자 승인 필요 |
| **model** | 핸드오프 실행 시 사용할 모델 (선택) |

## 커스텀 에이전트 파일 위치

| 범위 | 위치 |
|------|------|
| 워크스페이스 | `.github/agents/` 폴더 |
| 워크스페이스 (Claude 형식) | `.claude/agents/` 폴더 |
| 사용자 프로필 | `~/.copilot/agents/` 또는 VS Code 프로필 디렉토리 |

### 파일명
- `.agent.md` 확장자 사용
- VS Code는 `.github/agents/` 폴더의 모든 `.md` 파일도 감지

### 위치 커스터마이징
- `chat.agentFilesLocations` 설정으로 추가 위치 지정 가능

## 커스텀 에이전트 파일 구조

### 헤더 (선택)

YAML 프론트매터로 메타데이터 설정:

```yaml
---
name: "보안 리뷰어"
description: "코드의 보안 취약점을 검토하고 개선 제안"
argument-hint: "[리뷰 대상] [초점 영역]"
tools: ['search', 'codebasearch']
model: "Claude Sonnet 4.5"
handoffs:
  - label: "구현 수정"
    agent: implementation
    prompt: "제시된 보안 개선사항을 구현하세요."
---
```

### 헤더 필드 상세

| 필드 | 필수 | 설명 |
|------|------|------|
| **name** | 선택 | 에이전트 이름 (드롭다운에 표시) |
| **description** | 선택 | 에이전트 설명 (선택자 텍스트) |
| **argument-hint** | 선택 | 사용자 입력 가이드 |
| **tools** | 선택 | 사용 가능한 도구 목록 |
| **agents** | 선택 | 서브에이전트로 사용 가능한 에이전트 목록 |
| **model** | 선택 | 사용할 AI 모델 (배열로 우선순위 지정 가능) |
| **user-invocable** | 선택 | 드롭다운에 표시 여부 (기본값: true) |
| **disable-model-invocation** | 선택 | 서브에이전트로 호출 방지 (기본값: false) |
| **target** | 선택 | 대상 환경 (vscode 또는 github-copilot) |
| **mcp-servers** | 선택 | GitHub Copilot용 MCP 서버 목록 |
| **hooks** | 선택 | 에이전트 스코프 훅 (미리보기) |
| **handoffs** | 선택 | 핸드오프 목록 |

### 헤더 필드 상세 설명

#### **tools** 필드
```yaml
tools:
  - 'search'
  - 'web'
  - 'editFiles'
  - 'createFiles'
  - 'database/*'  # MCP 서버의 모든 도구
```

- 내장 도구, 도구 세트, MCP 도구, 확장 도구 포함 가능
- `<server>/*`로 MCP 서버의 모든 도구 포함 가능
- 사용 불가능한 도구는 무시됨

#### **agents** 필드
```yaml
agents:
  - 'planner'
  - 'reviewer'
agents: '*'  # 모든 에이전트 허용
agents: []   # 서브에이전트 금지
```

#### **model** 필드 (단일 또는 배열)
```yaml
model: "Claude Sonnet 4.5"

model:
  - "GPT-5 (copilot)"
  - "Claude Sonnet 4.5 (copilot)"
  - "o1 (copilot)"
```
- 배열의 경우 첫 번째 사용 가능한 모델 사용

### 본문

마크다운으로 에이전트의 역할과 지침을 정의합니다:

```markdown
---
name: "보안 리뷰어"
description: "코드 보안 검토"
tools: ['search', 'codeBasearchive']
---

# 보안 코드 리뷰

당신은 경험 많은 보안 전문가입니다.

## 리뷰 포커스

1. **인증/인가**: 제대로 구현되어 있는가?
2. **입력 검증**: 모든 입력이 검증되는가?
3. **데이터 보안**: 민감 정보가 보호되는가?

## 출력 포맷

각 문제에 대해:
- 심각도 (높음/중간/낮음)
- 설명
- 수정 방안
```

### 도구 참조

본문에서 도구를 참조하려면:
```markdown
#tool:web/fetch를 사용하여 외부 API 호출
#tool:editFiles로 파일 수정
```

## 커스텀 에이전트 생성

### 방법 1: 에이전트 커스터마이징 에디터

1. 챗 뷰에서 설정(기어) 아이콘 선택
2. 에이전트 탭에서 `New Agent` 선택
3. 워크스페이스 또는 사용자 선택
4. 파일명 입력
5. `.agent.md` 파일 작성

### 방법 2: 명령 팔레트
```
Chat: New Custom Agent
```

### 방법 3: 빠른 메뉴
```
/agents
```

### 방법 4: AI로 생성
```
/create-agent
```
- 역할 설명 입력
- AI가 질문 후 `.agent.md` 생성

또는 진행 중인 대화에서:
```
"이런 종류의 작업을 위한 에이전트를 만들어줘"
```

## Claude 에이전트 형식

`.claude/agents/` 폴더의 `.md` 파일은 Claude 형식을 지원합니다:

```yaml
---
name: "보안 리뷰어"
description: "코드 보안 검토"
tools: "Search, Edit, Grep, Bash"
disallowedTools: "Shell"
---
```

| 필드 | 설명 |
|------|------|
| **name** | 에이전트 이름 (필수) |
| **description** | 설명 |
| **tools** | 쉼표 구분 도구 목록 |
| **disallowedTools** | 쉼표 구분 금지 도구 목록 |

VS Code는 Claude 도구명을 VS Code 도구명으로 자동 매핑합니다.

## 에이전트 드롭다운 커스터마이징

### 에이전트 표시/숨김

1. 에이전트 드롭다운에서 "커스텀 에이전트 설정" 선택
2. 에이전트에 호버하여 눈 아이콘 선택

### 다중 에이전트 관리

여러 에이전트가 있을 때:
- 자주 사용하는 에이전트는 표시
- 특수 목적 에이전트는 숨김
- 서브에이전트로만 사용하는 에이전트는 숨김

## 도구 목록 우선순위

커스텀 에이전트와 프롬프트 파일에서 `tools`를 설정할 때:

**우선순위 (높음 → 낮음):**
1. 프롬프트 파일의 도구 (있으면)
2. 프롬프트 파일이 참조하는 커스텀 에이전트의 도구 (있으면)
3. 선택된 에이전트의 기본 도구

## 팀 전체로 에이전트 공유

### 워크스페이스 레벨 공유

1. `.github/agents/` 폴더에 에이전트 정의
2. 파일을 버전 관리에 포함
3. 팀 멤버가 저장소 체크아웃 시 자동으로 사용 가능

### 조직 레벨 공유

GitHub 조직 레벨에서 커스텀 에이전트 정의:

**활성화:**
```
github.copilot.chat.organizationCustomAgents.enabled: true
```

팀 멤버가 자동으로 발견하고 사용 가능합니다.

## 보안 고려사항

### 최소 권한 원칙

커스텀 에이전트는 필요한 도구만 포함:
- 읽기 전용 작업: 조회 도구만 포함
- 쓰기 작업: 편집 도구 포함
- 보안 검토: 위험한 도구 제외

### 예시

```yaml
# 계획 에이전트 (읽기 전용)
tools: ['search', 'web', 'codeBasesearch']

# 리뷰 에이전트 (읽기 전용)
tools: ['search', 'codeBasesearch', 'grep']

# 구현 에이전트 (읽기/쓰기)
tools: ['editFiles', 'createFiles', 'deleteFiles', 'search']
```

## 문제 해결

### 에이전트가 드롭다운에 표시되지 않음

1. 파일이 올바른 위치에 있는가?
   - `.github/agents/` 폴더

2. 파일명이 맞는가?
   - `.agent.md` 또는 `.md` 확장자

3. `user-invocable: false`가 아닌가?

4. 설정에서 `chat.agentFilesLocations` 확인

### 도구가 사용 불가능하다고 나옴

- 도구명을 정확히 입력했는가?
- 도구가 현재 환경에서 사용 가능한가? (예: MCP 서버 실행 중인가?)

### 에이전트 제거

**완전 제거:**
1. `.agent.md` 파일 삭제
2. 에이전트 설정 메뉴에서 휴지통 아이콘 선택

**확장으로부터의 에이전트:**
- 확장 제거 필요
- 또는 드롭다운에서만 숨기기 가능

### 에이전트의 출처 확인

1. 에이전트 드롭다운에서 "커스텀 에이전트 설정" 선택
2. 에이전트에 호버하면 출처 표시됨
3. 또는 에이전트 디버그 로그 확인

## 실제 예제

### 예제 1: 계획 에이전트

```markdown
---
name: "계획가"
description: "프로젝트 계획 및 아키텍처 검토"
tools: ['search', 'web', 'codeBasesearch']
handoffs:
  - label: "구현 시작"
    agent: implementation
    prompt: "위 계획에 따라 구현을 시작하세요"
---

# 계획 및 아키텍처 에이전트

당신은 경험 많은 소프트웨어 아키텍트입니다.

## 역할
- 프로젝트 요구사항 분석
- 기술 스택 제안
- 상세 구현 계획 수립

## 산출물
1. 요구사항 요약
2. 기술 스택 추천
3. 단계별 구현 계획
4. 잠재적 위험 요소
```

### 예제 2: 코드 리뷰어 (읽기 전용)

```markdown
---
name: "코드 리뷰어"
description: "코드 품질, 성능, 보안 검토"
tools: ['search', 'codeBasesearch']
---

# 코드 리뷰어

당신은 시니어 개발자로서 엄격한 코드 리뷰를 수행합니다.

## 검토 항목
1. 코드 품질 (가독성, 유지보수성)
2. 성능 (최적화 가능성)
3. 보안 (취약점)
4. 테스트 커버리지

## 출력 형식
- 각 문제에 대해 구체적 개선 제안
- 우수 사례 하이라이트
```

- 파일명을 `.agent.md`로 변경
- 같은 폴더에 배치 (`chat.agentFilesLocations` 참조)
- 기존 기능 유지
