# VS Code 에이전트 서브에이전트 정리

원문: https://code.visualstudio.com/docs/agents/subagents

---

## 1. 한 줄 요약

서브에이전트는 메인 에이전트가 복잡한 작업을 작은 하위 작업으로 나눠 위임하는 방식입니다. 각 하위 작업을 독립적으로 처리해 더 깔끔한 결과를 얻는 데 도움을 줍니다.

---

## 2. 언제 쓰나?

다음과 같은 상황에서 특히 유용합니다.

- 코드 분석, 조사, 리서치가 여러 단계로 나뉘는 작업
- 병렬로 독립적인 작업을 처리해야 하는 경우
- 메인 컨텍스트를 깔끔하게 유지하고 싶을 때
- 리뷰, 탐색, 구현 등을 역할별로 분리하고 싶을 때

---

## 3. 기본 작동 방식

1. 사용자가 복잡한 작업을 설명합니다.
2. 메인 에이전트가 작업 중 일부를 서브에이전트에 위임할지 판단합니다.
3. 서브에이전트가 독립적인 컨텍스트에서 작업합니다.
4. 결과를 요약해서 메인 에이전트에게 돌려줍니다.
5. 메인 에이전트가 전체 흐름을 이어갑니다.

즉, 서브에이전트는 “작업의 일부를 분리해서 맡기는 작은 보조 에이전트”입니다.

---

## 4. 서브에이전트가 보이는 방식

- 채팅에서 접을 수 있는 도구 호출 형태로 표시됩니다.
- 어떤 작업을 수행 중인지 확인할 수 있습니다.
- 필요하면 상세 내용을 확장해 내부 도구 호출과 결과까지 볼 수 있습니다.

---

## 5. 커스텀 에이전트를 서브에이전트로 쓰기

커스텀 에이전트는 메인 에이전트의 하위 작업으로도 사용할 수 있습니다.

### 제어 포인트

- `user-invocable: false`를 설정하면 사용자 드롭다운에는 보이지 않지만, 다른 에이전트가 호출하는 서브에이전트로는 쓸 수 있습니다.
- `disable-model-invocation: true`를 사용하면 일반적인 자동 호출을 막을 수 있습니다.
- `agents` 속성을 지정하면 어떤 서브에이전트만 허용할지 제한할 수 있습니다.

---

## 6. 모델 선택

서브에이전트는 다음 우선순위로 모델을 결정합니다.

1. 명시적으로 지정된 모델
2. 커스텀 에이전트의 모델 설정
3. 메인 대화의 모델

즉, 리서치, 리뷰, 구현 같은 역할마다 다른 모델을 사용하는 것도 가능합니다.

---

## 7. 중첩 서브에이전트

기본적으로 서브에이전트는 다시 다른 서브에이전트를 호출할 수 없습니다. 하지만 설정을 활성화하면 중첩 구조도 가능합니다.

이 기능은 다음처럼 쓰입니다.

- 큰 작업을 나누고
- 더 작은 하위 작업으로 다시 분할하고
- 재귀적으로 처리하는 패턴

---

## 8. 흔한 패턴

### Coordinator + Worker 패턴

- 메인 에이전트가 전체 흐름을 조율합니다.
- 각 역할별로 Planner, Reviewer, Implementer 같은 서브에이전트를 둡니다.

### Multi-perspective 리뷰

- 코드 리뷰를 여러 관점으로 나눠 각각 다른 서브에이전트가 처리합니다.
- 예: 정확성, 보안, 코드 품질, 아키텍처 관점

---

## 9. 핵심 정리

서브에이전트는 “복잡한 작업을 작은 역할로 나눠 맡기는 방식”입니다. 맥락을 분리하고, 역할별로 집중하게 만들며, 더 체계적인 에이전트 워크플로를 구성하는 데 유용합니다.
