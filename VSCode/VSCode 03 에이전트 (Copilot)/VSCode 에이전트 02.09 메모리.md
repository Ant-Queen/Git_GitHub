# VS Code 에이전트 메모리 정리

원문: https://code.visualstudio.com/docs/agents/memory

---

## 1. 한 줄 요약

메모리 기능을 사용하면 에이전트가 이전 대화나 작업에서 배운 내용을 기억하고, 나중에 다시 유용하게 활용할 수 있습니다.

---

## 2. 왜 쓰나?

- 자주 쓰는 코드 스타일, 팀 규칙, 프로젝트 컨벤션을 기억하게 할 수 있습니다.
- 작업 중 생성한 임시 메모를 세션 단위로 유지할 수 있습니다.
- 여러 대화에서 동일한 맥락을 다시 설명하지 않아도 됩니다.

---

## 3. 메모리의 범위

### 사용자 메모리

- 모든 워크스페이스와 대화에 걸쳐 유지됩니다.
- 개인 선호도, 자주 쓰는 명령, 일반적인 습관에 적합합니다.

### 저장소 메모리

- 현재 워크스페이스에만 국한됩니다.
- 프로젝트 구조, 아키텍처 결정, 빌드 규칙 등에 적합합니다.

### 세션 메모리

- 현재 대화 세션에만 유지됩니다.
- 작업 중 임시 계획이나 진행 상황을 기록하는 데 적합합니다.

---

## 4. 메모리 저장과 불러오기

자연어로 요청하면 에이전트가 적절한 메모리 파일에 저장합니다.

예시:

- `Remember that I prefer tabs over spaces.`
- `Remember that this project uses conventional commits.`

나중에 같은 주제를 다시 묻는다면 에이전트가 저장된 메모리를 참고합니다.

---

## 5. 메모리 파일 관리

VS Code에서는 다음 명령으로 메모리 파일을 확인하거나 정리할 수 있습니다.

- `Chat: Show Memory Files`
- `Chat: Clear All Memory Files`

메모리 파일은 클릭 가능한 링크로 표시되어 직접 열어볼 수 있습니다.

---

## 6. 로컬 메모리와 Copilot Memory

### 로컬 메모리

- VS Code 로컬 환경에 저장됩니다.
- 사용자/저장소/세션 범위로 관리할 수 있습니다.
- VS Code 안에서 주로 사용합니다.

### Copilot Memory

- GitHub 호스팅 기반 메모리입니다.
- 저장소 수준의 지식을 여러 Copilot 표면에서 공유할 수 있습니다.
- 별도 설정이 필요할 수 있습니다.

---

## 7. 실무 팁

- 개인 스타일은 사용자 메모리에 넣고, 프로젝트 규칙은 저장소 메모리에 넣는 것이 좋습니다.
- 세션 메모리는 임시 계획 같은 일시적인 정보에만 쓰는 것이 좋습니다.
- 오래된 메모리는 주기적으로 정리해 stale 정보가 남지 않도록 해야 합니다.

---

## 8. 핵심 정리

메모리는 에이전트가 “이전 대화에서 배운 것”을 기억하게 해 주는 기능입니다. 적절히 활용하면 반복 설명을 줄이고, 프로젝트 컨텍스트를 더 잘 유지할 수 있습니다.
