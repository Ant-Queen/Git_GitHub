# VS Code 에이전트 세션 인사이트

GitHub Copilot 세션은 작업 이력을 검색하고 요약할 수 있는 기록으로 저장됩니다. 세션 인사이트를 통해 지난 작업을 빠르게 검토하고, 스탠드업 보고서 생성, 팁 확인, 검색을 수행할 수 있습니다.

## 1. Chronicle 명령어

Chat 입력에 다음 명령어를 사용하여 세션 기록을 조회합니다.

- `/chronicle:standup`
  - 최근 코딩 세션을 브랜치와 저장소별로 그룹화하여 스탠드업 보고서를 생성
  - 기본적으로 지난 24시간을 요약
  - 편집한 파일, 참조한 PR/이슈, 진행 상태 등을 포함
- `/chronicle:tips`
  - 최근 세션 기록(보통 7일)을 분석하여 Copilot을 더 효율적으로 사용하는 방법 제안
  - 실제 사용 패턴(도구 사용 빈도, 프롬프트 작성 방식 등)에 기반하여 권장 사항 제공
- `/chronicle:cost-tips`
  - 최근 세션을 분석하여 토큰 사용량과 비용을 줄일 기회 찾기
- `/chronicle:search <query>`
  - 키워드, 파일 경로, PR/이슈 참조로 세션 검색
  - 세션 요약, 대화 내용, 파일 경로, 체크포인트 노트 등을 전체 텍스트 인덱싱하여 결과를 반환
  - 결과에는 세션 ID와 타임스탬프가 포함되어 관련 세션으로 바로 이동 가능
- `/chronicle:reindex`
  - 로컬 세션 인덱스를 재구성하고 세션 데이터를 계정에 동기화

## 2. 자유 형식 질문

채팅에서 자연어로 과거 세션 기록에 대해 질문할 수 있습니다.

- 예: `어제 수정한 파일이 뭐야?`
- 예: `payments API 관련 작업을 했었어?`

`/chronicle:search`는 직접 검색을 수행하는 반면, 자유 형식 질문은 의미 기반 이해를 사용하여 관련 세션을 찾아 답변합니다.

## 3. 기록되는 항목

로컬 세션 저장소는 각 채팅 세션에 대해 다음을 기록합니다.

- 세션 메타데이터: 저장소, 브랜치, 작업 디렉터리, 타임스탬프, 사용한 에이전트 또는 참가자
- 대화 내용: 사용자 메시지(최대 1,000자) 및 어시스턴트 응답(최대 5,000자)
- 수정한 파일: `replace_string_in_file`, `create_file`, `read_file`, `apply_patch` 등 도구 호출로 터치한 파일 경로
- 외부 참조: GitHub MCP 도구 호출 및 터미널 명령에서 추출된 PR 번호, 이슈 번호, 커밋 SHA

데이터는 로컬 SQLite 데이터베이스에 저장됩니다. 토큰, API 키, 비밀번호, 연결 문자열 같은 비밀 정보는 클라우드 동기화 전에 자동으로 필터링됩니다.

## 4. 세션 저장소 재색인

세션이 누락되었거나 데이터베이스가 손상된 경우 인덱스를 다시 빌드합니다.

- `/chronicle:reindex` 명령어 실행
- 명령 팔레트에서 `github.copilot.chronicle.reindex` 실행 가능

다음과 같은 경우 재색인이 도움이 됩니다.

- 백업에서 세션 파일을 복원한 후
- 예기치 않은 충돌로 데이터가 저장되지 않은 후
- 세션 디렉터리를 수동으로 삭제한 후
- 세션 동기화를 다시 활성화한 후

## 5. 관련 콘텐츠

- 세션 동기화: `session-sync`
- 채팅 세션 관리: `chat-sessions`
- 설정 참조: `copilot-settings`

> 이 문서는 VS Code 공식 `Session Insights` 페이지를 바탕으로 한국어로 요약 정리한 내용입니다.
