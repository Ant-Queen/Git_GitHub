# VS Code Agents 창

VS Code Agents 창은 에이전트 중심 작업을 위한 전용 창입니다. 에디터 창은 단일 워크스페이스 중심 코딩에 최적화되어 있는 반면, Agents 창은 여러 프로젝트와 세션을 한곳에서 관리하고 에이전트를 조율하기에 적합합니다.

Agents 창은 기존 Copilot CLI, Copilot Cloud, Claude 에이전트 세션을 동일하게 인식하며, 여러 워크스페이스 간 세션을 열어두고 전환할 수 있습니다.

## 1. 전제 조건

- Visual Studio Code 설치
- GitHub Copilot 사용 권한
- VS Code에서 GitHub Copilot 설정 및 인증 완료

## 2. Agents 창 열기

Agents 창을 여는 방법:

- VS Code 제목 표시줄에서 `Open in Agents` 버튼 선택
- 명령 팔레트에서 `Chat: Open Agents Window` 실행 (`Ctrl+Shift+P`)
- 환영 페이지에서 Agents 창 열기 선택
- 명령줄에서 `code --agents` 실행
- 브라우저에서 `https://insiders.vscode.dev/agents` 열기

Agents 창은 GitHub 인증과 Copilot 구독을 필요로 하며, 이미 VS Code에 로그인한 상태라면 동일한 계정으로 연결됩니다.

## 3. 인터페이스 개요

Agents 창의 주요 구성 요소:

1. 세션 목록
   - 사이드바에서 현재 활성 세션과 워크스페이스별 그룹을 확인
   - 세션 이름 변경, 완료 표시, 고정 등 명령 실행 가능
2. 맞춤화 패널
   - 에이전트 동작을 프로젝트와 워크플로우에 맞게 조정하는 설정 접근
3. 채팅 영역
   - 대화 기록과 프롬프트 입력창
   - 여러 세션을 나란히 열어 동시에 비교 가능
4. 변경 사항 패널
   - 에이전트가 만든 파일 변경과 생성된 아티팩트 검토
   - 워크스페이스 파일 탐색기 보기 제공

## 4. 에이전트 세션 시작

Agents 창에서 새 세션을 시작하려면:

1. 사이드바 상단의 `New` 선택 또는 `Ctrl+N` 입력
2. 워크스페이스 드롭다운에서 로컬 폴더 또는 GitHub 리포지토리 선택
   - 워크스페이스를 신뢰하지 않은 경우 신뢰 여부 확인 필요
3. 에이전트 유형 선택
   - 폴더: Copilot CLI 또는 Claude 에이전트 선택 가능
   - 리포지토리: Copilot Cloud 에이전트로 세션 시작
4. Copilot CLI 세션은 작업 isolation 설정 선택
   - Worktree isolation: Git worktree를 사용해 변경 사항을 메인 워크스페이스와 분리
   - Folder isolation: 현재 워크스페이스에 직접 변경 사항 적용
5. 커스텀 에이전트 및 언어 모델 선택 가능
6. 프롬프트 입력 후 Enter

에이전트는 작업을 단계로 분해하고 코드 작성, 명령 실행, 오류 수정 등을 수행합니다.

## 5. 파일 변경 관리 및 검토

변경 사항 패널은 에이전트 세션 중 발생한 편집 내역을 자세히 보여줍니다.

- Files 탭: 워크스페이스의 파일 탐색기 뷰
- Changes 탭: 에이전트가 변경, 추가, 삭제한 파일 목록
- Branch Changes 드롭다운으로 표시할 변경 항목 선택

파일을 선택하면 현재 워크스페이스 상태와 에이전트 편집 내용을 비교하는 diff 뷰를 연다.

diff 뷰에서는:

- 사이드바 또는 모달 창으로 열기
- 표시 모드 전환
- 편집 내부를 클릭하고 `Add Feedback`로 에이전트에게 수정 요청

변경 사항에 대한 후속 작업:

- Commit: 폴더 isolation에서 변경 사항 바로 커밋
- Merge: worktree isolation에서 병합 및 PR 생성
- Checkout: Copilot Cloud 세션에서 세션 브랜치 체크아웃
- Discard: 원하지 않는 수정사항 폐기

새 세션 생성 시 Files 패널의 동기화 버튼으로 베이스 브랜치 최신 상태를 가져올 수 있습니다.

## 6. 에이전트 변경 사항 로컬 검증

Agents 창에서 세션 컨텍스트에 맞춰 작업을 검증할 수 있습니다.

- 세션을 열고 `Tasks` 드롭다운에서 `Add Task` 선택
- 작업 이름, 명령(예: `npm run build`, `pytest`), 실행 옵션, 저장 위치 설정
- 저장된 작업은 세션 컨텍스트에서 실행 가능

브라우저 기반 동작이 필요한 경우 통합 브라우저를 사용할 수 있습니다.

- 채팅 세션에서 `localhost` 링크 선택
- 명령 팔레트에서 `Browser: Open Integrated Browser` 실행
- 통합 브라우저는 세션 간 전환 시에도 동일 페이지 상태 유지

터미널 명령 실행은 제목 표시줄의 `Open Terminal` 아이콘으로 현재 세션 작업 디렉터리에서 실행할 수 있습니다.

## 7. 원격 머신에서 세션 열기

Agents 창은 SSH 또는 Dev Tunnel을 통해 원격 머신에서 세션을 실행할 수 있습니다.

### SSH 연결

1. `New` 또는 `Ctrl+N`으로 새 세션 시작
2. 워크스페이스 드롭다운에서 `Remote` 탭 선택 후 `SSH` 선택
3. SSH 연결 문자열 입력
4. 원격 머신에서 폴더 선택
5. 프롬프트 입력 후 시작

### Dev Tunnel 연결

1. `New` 또는 `Ctrl+N`으로 새 세션 시작
2. 워크스페이스 드롭다운에서 `Remote` 탭 선택 후 `Tunnels` 선택
3. 활성 Dev Tunnel 선택
4. 원격 머신 폴더 선택
5. 프롬프트 입력 후 시작

중요: Dev Tunnel은 인증된 상태여야 하며, 익명 접근이 허용된 경우 보안 위험이 커집니다.

## 8. 브라우저에서 Agents 창 사용

브라우저에서도 Agents 창을 사용 가능합니다.

- 원격 호스트에서 `code-insiders tunnel` 또는 `code tunnel` 실행
- 브라우저에서 `https://insiders.vscode.dev/agents` 접속
- GitHub로 로그인 후 터널 호스트 선택
- 원격 머신의 폴더를 선택하고 세션 시작

호스트 바에서 호스트 상태 표시:

- Online: 연결 가능
- Offline: 터널이 실행되지 않음

브라우저 기반 Agents 창은 원격 머신에서 에이전트 세션을 채팅, 변경 검토, 세션 관리 용도로 가볍게 사용할 수 있습니다.

## 9. 서브 세션 생성

활성 세션에서 별도의 병렬 작업을 수행하려면 서브 세션을 만듭니다.

- 활성 세션에서 `New Sub-Session (+)` 선택
- 채팅 영역에 새로운 탭이 생성됨
- 부모 세션 대화 기록은 복사되지 않고, 동일 워크스페이스/워크트리를 공유

서브 세션은 독립적인 작업 방향을 탐색할 때 유용합니다.

## 10. 여러 세션을 나란히 열기

Agents 창에서 여러 세션을 병렬로 열어 비교할 수 있습니다.

- 세션 목록에서 우클릭 후 `Open to the Side` 선택
- 세션을 드래그 앤 드롭하여 view 영역에 배치
- `Alt` 키를 누른 상태로 세션 선택

한 번에 활성화되는 세션 뷰는 하나이며, 터미널/파일/변경 보기 등은 활성 세션을 기준으로 표시됩니다.

## 11. 세션 관리

세션 목록은 모든 활성 세션을 표시합니다.

- 프로젝트 또는 시간별로 그룹화 가능
- 세션 이름, 워크스페이스, 에이전트 유형, 파일 변경 상태 확인
- 필터와 검색 기능으로 원하는 세션 찾기
- 세션 선택 시 대화 기록 및 변경 내용 표시
- 우클릭으로 이름 변경, 삭제 등의 관리 옵션 수행

고급 관리 기능(보관, 포크, 체크포인트, 내보내기)은 `Manage chat sessions` 문서에서 확인합니다.

## 12. 프로젝트 및 워크플로우에 맞게 에이전트 커스터마이즈

맞춤화 패널에서 다음을 관리할 수 있습니다.

- Agents: 특정 도구와 지침을 가진 맞춤 에이전트 정의
- Skills: 관련 상황에서 로드되는 재사용 가능한 지침 폴더 추가
- Instructions: AI가 코드를 생성할 때 따를 가이드라인 설정
- Hooks: 에이전트 세션 생명 주기에서 셸 명령 실행
- MCP Servers: 외부 도구와 서비스 연결
- Plugins: 미리 구성된 커스터마이즈 번들 설치

패널에서 워크스페이스별 또는 사용자 전체 적용 범위를 선택하고 새 커스터마이즈를 추가하거나 편집할 수 있습니다.

## 13. 폴더 신뢰

새 폴더나 리포지토리를 열면 폴더 신뢰 여부를 묻습니다.

- 신뢰하지 않으면 에이전트 세션 시작 불가
- VS Code 에디터 창과 동일한 워크스페이스 신뢰 상태 공유

## 14. GitHub 계정 전환

상단 오른쪽 계정 아이콘에서 `Sign out` 후 다른 계정으로 로그인합니다.

## 15. Agents 창 설정 구성

Agents 창은 VS Code 설정을 공유합니다.

- Agents 창에만 적용할 설정은 설정 파일에서 Agents 창 섹션으로 스코프 지정
- 설정 편집기는 `Ctrl+,`로 열 수 있음

## 16. Agents 창에서 VS Code 확장 사용

Agents 창은 확장을 실행할 수 있습니다.

- 테마, 문법, 언어, 키바인딩 같은 정적 확장은 기본 활성화
- 일부 상위 100개 Marketplace 확장도 활성화됨
- `extensions.supportAgentsWindow` 설정을 사용해 특정 확장을 수동으로 활성화 가능

확장 사용 시 주의사항:

- 활성화하려는 확장은 기본 VS Code 프로필에 설치되어 있어야 함
- Agents 창에서 동작이 예상과 다를 수 있으므로 문제가 있을 경우 GitHub 이슈 제출

## 17. 제한 사항

현재 Agents 창의 주요 제한 사항:

- 통합 브라우저를 직접 여는 기능은 없음
- 지원 에이전트 유형: Copilot CLI, Copilot Cloud, Claude 에이전트
- GitHub 리포지토리에서만 Copilot Cloud 세션 지원
- Plan 에이전트 드롭다운이 없음 (Copilot CLI/Claude 세션에서 `/plan` 명령 사용 가능)
- Claude 에이전트 세션은 서브 세션 미지원
- 멀티 루트 세션은 아직 미지원
